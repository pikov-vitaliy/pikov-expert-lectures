# EP01 — Where Secure Development Begins

**Проект первого выпуска для репетиции.** Серия *Secure Software Development in Practice*. Автор: Vitaliy Pikov. Подготовлено 6 сентября 2026 года.

Тема: введение в серию, история безопасной разработки, создание редакции ГОСТ 2016 года и процесс **5.1 «Планирование процессов разработки безопасного программного обеспечения»** ГОСТ Р 56939-2024. Материалы выступления — на английском. **29 слайдов, рабочая длительность 42 минуты 20 секунд**; окончательная длительность определяется репетицией и монтажом, увеличение автором разрешено.

## Начать подготовку

2. Прочитать [план и режиссуру](EP01-plan.md), затем [полный английский сценарий по слайдам](EP01-script-en.md).
3. Сделать пробную запись по [памятке для репетиции](EP01-rehearsal.md) и сверить её с [расчётом хронометража](EP01-timing.md).

## Как редактировать

Изменять содержание и речь в `EP01-script-en.md`, сохраняя поля `Seconds`, `Section`, `Layout`, `Lead`, `Items`, `Sources`, `Speech`, `Cue` и связи с иллюстрациями. Плановая общая длительность задаётся строкой `Target: mm:ss`; число слайдов определяется автоматически, номера идут подряд от 1. Для контакта на последнем слайде используется поле `Contact: имя | видимый адрес | HTTPS URL`. Содержание рисунков редактируется в JSON-блоках [EP01-visuals.md](EP01-visuals.md); текст русской лекции и ссылки на её рисунки — в `PVS-2025-07-02-lecture.md`.

Собирать комплект из папки EP01 в таком порядке:

```powershell
py -3.14 build-visuals.py
py -3.14 build-content.py
py -3.14 build-review.py
```

`build-visuals.py` создаёт локальные SVG из каталога; `build-content.py` обновляет `assets/episode-data.js` и `EP01-timing.md`, проверяя сумму времени; `build-review.py` обновляет обе HTML-страницы из актуальных Markdown и данных выпуска. Источники для отображения задаются в `build-content.py`; подробная методическая запись — в `EP01-sources.md`. Изменение только готового HTML или SVG без соответствующего Markdown-источника не является завершённой правкой.

Для двух HTML-материалов выполнить `py -3.14 build-review.py` (нужны библиотеки `markdown` и `beautifulsoup4`, доступные в этой среде). Генератор находится в репозитории, читает актуальные Markdown и данные слайдов, не зависит от временных HTML предыдущих задач. `--check` проверяет сборку без записи. После браузерной проверки `--archive "V:\tmp\codex\YYYY-MM-DD\YYYY-MM-DD-тема.html" --qa-text "Результат проверки"` создаёт новую архивную копию; существующий архив не перезаписывается. После изменений перезагрузить страницу.

Презентация использует обычные HTML, CSS и JavaScript, локальные файлы и системные шрифты. Сервер, сборщик и интернет для чтения не требуются. Для проверки через локальный сервер: `python -m http.server 8765 --bind 127.0.0.1 --directory .`; открыть `http://127.0.0.1:8765/`. Это локальный просмотр, а не публикация сайта. Политика конкретного встроенного браузера может ограничивать открытие локальных файлов.

## Визуальная подача

На слайдах **03, 04, 05, 08, 11, 12, 13, 15, 16, 17, 19, 20, 21, 22, 23 и 24** текстовые списки дополнены или заменены объясняющей графикой: шкалами времени, границами области, циклами работы, картой планирования и сопоставлением требований. На слайдах 04 и 24 повторяется одна история импортёра; на слайдах 16 и 22 — одна структура требований и соответствующих свидетельств. Диаграмма 60 + 24 + 12 = 96 человеко-часов обозначена учебной оценкой.

В русской лекции — **семь рисунков**: история методологий, подготовка ГОСТ, поддерживаемый процесс, направления проверок, свидетельства планирования, сопровождение и практическая работа. Их содержание сохраняется синхронно в Markdown и HTML. Локальные SVG не требуют внешних сервисов; при передаче Markdown вместе с ним передаются рисунки по его относительным ссылкам.

Основной видимый текст и подписи используют начертания **600/700**. Схемы заменяют часть плотного текста, а подробное объяснение остаётся в речи и лекции. Браузерная проверка всех 29 слайдов при 720p, Full HD и 4K и мобильного чтения выполнена: [результаты проверки](EP01-visual-review.md). После будущих правок проверку повторять; качество фактической записи и печати оценивается отдельно.

Из дискуссии в практику включены анализ уже работающих процессов, ресурсные оценки, регулярность проверок и использование существующих систем для свидетельств.
