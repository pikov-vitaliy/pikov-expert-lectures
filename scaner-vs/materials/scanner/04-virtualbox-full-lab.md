# Вариант 3. Полный изолированный стенд VirtualBox

## Назначение

Полный стенд позволяет пройти весь цикл Сканер-ВС 7 на нескольких разнородных активах.

## Состав

| Роль | Рекомендуемая система | Пример адреса в Host-only сети |
|---|---|---|
| Сканер | Astra Linux + Сканер-ВС 7 | `192.168.56.10` |
| Уязвимый Linux | Metasploitable 2 | `192.168.56.20` |
| Windows-цель | Учебная Windows 10/11 | `192.168.56.30` |

Адреса являются примерами. Используйте собственную согласованную подсеть.

## Критическое отличие от старой методички версии 6

В старом стенде применялся сетевой мост и были опубликованы общие слабые пароли. В новом практикуме это запрещено:

- у целей нет Bridged Adapter;
- Metasploitable подключена только к Host-only/Internal Network;
- общие пароли из старой методички не используются;
- каждый стенд получает собственные временные реквизиты;
- старые OVA-образы и ссылки не включаются в комплект.

## Подготовка гипервизора

1. Установите поддерживаемую версию VirtualBox из официального источника.
2. Создайте Host-only или Internal Network с уникальным именем, например `scanner-lab`.
3. Подключите к ней все три ВМ.
4. Для временного обновления сканера можно добавить NAT вторым интерфейсом только к ВМ сканера; отключите его до исследования сети.
5. У целей не должно быть NAT или моста во время практики.
6. Создайте снимки всех ВМ до настройки WinRM/SSH.

## Подготовка Windows

1. Создайте временную учебную запись локального администратора.
2. Получите и проверьте vendor-скрипт `winrm.ps1` из поставки Сканер-ВС.
3. Настройте HTTPS WinRM/5986 только для адреса сканера.
4. Проверьте соединение в Сканер-ВС.
5. Зафиксируйте план удаления временной записи и правила брандмауэра.

## Подготовка Linux

1. Убедитесь, что SSH доступен только внутри `scanner-lab`.
2. Для обычной Linux-цели используйте отдельный ключ и контролируемый `sudo`.
3. Metasploitable рассматривайте как намеренно уязвимую систему; не храните на ней реальные данные.
4. Не ослабляйте `StrictModes` на производственных Linux-системах.

## Задания

Выполните [общий сценарий четырех блоков](01-common-workflow.md):

1. построить карту сети и сверить три актива;
2. подключить Windows по WinRM и Linux по SSH;
3. провести инвентаризацию и поиск уязвимостей;
4. вручную проверить выбранные результаты;
5. выполнить парольную проверку только синтетической записи;
6. провести аудит конфигурации по поддерживаемому шаблону;
7. сформировать отчет и план повторной проверки.

## Аварийная остановка

Немедленно остановите ВМ и сообщите преподавателю, если:

- уязвимая машина получила внешний адрес;
- найден узел вне согласованной подсети;
- произошло срабатывание защиты хостовой/корпоративной сети;
- отчет содержит реальные учетные данные или персональные данные.

## Результат

Схема сети, паспорт ВМ, снимки до изменения, журнал задач и заполненный [шаблон отчета](REPORT-TEMPLATE.md).
