# Динамический анализ ПО

Публичный адрес: https://dast.pikov.expert/

`index.html` — полный авторский разбор первой редакции проекта национального
стандарта. `practice.html` — маршрут студенческой практики; `practice/` содержит
три методички. `downloads/` — PDF, Markdown, воспроизводимый ZIP и SHA-256.

Полный PDF проекта стандарта называется
`dynamic-analysis-national-standard-draft.pdf`; он сохранён побайтово.
`pns-dynamic-analysis.pdf` — отдельная печать авторского конспекта, а не стандарт.
Статус первой редакции явно указан на странице и в самом документе.

## Сопровождение

- Общий каталог: `../index.html` и `../_PROJECT/lectures.json`; русскую и новую
  главные генерируют `build-root-locales.mjs` и `build-new-site.mjs`.
- `node dast/_build/render-pdfs.mjs` печатает четыре авторских HTML-документа
  через Chromium с публичными HTTPS-адресами в ссылках PDF. После рендеринга
  нужно просмотреть документы и обновить их точные хеши в public-independence gate.
- `python -X utf8 dast/_build/build-package.py` создаёт студенческий ZIP из
  конкретных входов `student-source-manifest.json` и трёх методичек.
  Сборка релиза вызывает этот builder через `build-materials-zip.ps1`.
- Архив сохраняет имя, используемое в командах методичек. История Git,
  настройки редактора, служебные отчёты и готовые бинарники в выдачу не входят.
  Seed/crash/queue-данные сохраняются побайтово; двоеточия в именах AFL заменены
  на подчёркивания для Windows.
- `node --test _PROJECT/test-dast-publication.mjs` проверяет регистрацию,
  наличие материалов, PDF первоисточника и воспроизводимость ZIP.
- `node _PROJECT/qa-dast.mjs` проверяет локальную HTTP-версию в Chromium;
  `node _PROJECT/qa-dast.mjs --live` повторяет сценарии на опубликованном сайте
  и сверяет загрузки с файлами репозитория.

Домен использует собственный `.htaccess`: интерактивные схемы можно встраивать
только в страницы того же origin (`frame-ancestors 'self'`, `SAMEORIGIN`).
Внешние домены не получают права встраивания. `_build/` и этот README
исключаются из публичного релиза.

Публикация выполняется через общий `OPERATIONS_RUNBOOK.md` с областью
`pikov.expert` + `dast.pikov.expert`. Временный `_deploy_pikov_*` после live QA
архивируется локально и удаляется по проверенному абсолютному пути.
