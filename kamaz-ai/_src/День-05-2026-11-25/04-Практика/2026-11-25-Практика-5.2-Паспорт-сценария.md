# Практика к теме 5.2. Свой сценарий и его паспорт

**Время:** 4 академических часа (13:00–14:30 и 14:40–16:10).
**Что понадобится:** разрешённый сервис, дополнение к кейсу для пятого дня (документы 5-2, 5-3, 5-4, 5-6; ТЗ в них – редакция 1 из кейса первого дня), замер времени «до» из задания к модулю 5, таблица своих задач из практики 5.1 с отмеченной задачей для итоговой работы, шаблон паспорта (документ 5-2).
**Правило:** сценарий пробуем на учебных материалах или на материалах, отправку которых в выбранный сервис разрешают правила вашей организации. Если без рабочих документов задача теряет смысл, придумайте пример того же вида: те же поля, те же единицы, придуманные значения. В паспорте и приложениях итоговой работы – только учебные или придуманные данные. Настоящие документы и их фрагменты, в том числе обезличенные, туда не вставляются.

## Задание 1. Найти ошибки в паспорте, который составила модель (30 мин)

В документе 5-4 дополнения к кейсу – паспорт, который «составила модель» по просьбе инженера. В нём несколько ошибок разного рода. Сверяйтесь с основным кейсом, с образцом паспорта (документ 5-3) и с правилами курса.

| Фрагмент | Что не так | Как должно быть |
|---|---|---|
| | | |

Подсказка по видам ошибок: выбор сервиса без учёта данных, неверное правило защиты информации, запрос без исходных данных и с передачей решения модели, отказ от проверки, ссылка на несуществующий пункт, ошибки в расчёте эффекта, вывод, который из расчёта не следует, опасное развитие сценария.

Отдельно пересчитайте эффект правильно, взяв исходные данные из вопроса к модели и время проверки из документа 5-3.

**Результат:** таблица ошибок и правильный расчёт.

## Задание 2. Собрать и опробовать свой сценарий (60 мин)

Возьмите задачу, отмеченную в практике 5.1.

1. **Карточка задачи (10 мин).** Исходные данные – ожидаемый результат – критерии приёмки – ограничения.
2. **Запросы (15 мин).** Шаблон запроса из темы 1.2 или цепочка из двух-трёх запросов. Пишите полный текст, а не «попросить модель разобрать».
3. **Проба с проверкой (35 мин).** Полная операция на занятии не помещается дважды (у образца из документа 5-3 она занимает 30 минут), поэтому пробуют одну часть операции на двух коротких примерах. Для учебной задачи примеры заданы в документе 5-6: таблица соответствия по З-2 (простой) и по З-4 (трудный). Для своей задачи выберите по тому же правилу одну и ту же часть операции, простой и трудный случай. Ответ каждого примера проверьте по своему чек-листу из модуля 1 и запишите, что нашли и что пришлось исправить. Засеките отдельно время на запрос и чтение ответа и время на проверку. Время «до» для той же части операции запишите как оценку по опыту.

Единица сравнения: ________________________ (одна и та же для обоих примеров и для времени «до»).

| Пример | Минут на запрос и чтение | Минут на проверку | Минут «до», оценка | Что нашла проверка | Пригоден ли результат |
|---|---|---|---|---|---|
| 1 (простой) | | | | | |
| 2 (трудный) | | | | | |

Если сценарий не сработал на трудном примере, вы нашли его ограничение; запишите это ограничение в паспорт.

Для тех, у кого нет доступа к сервису: работайте в паре с участником, у которого он есть, по его экрану. Сценарий у каждого свой.

**Результат:** черновик паспорта, разделы 1–7, и таблица пробы.

## Задание 3. Оценить экономию времени (20 мин)

На занятии раздел 8 заполняется как **предварительная оценка** и так и подписывается. Сравнивать можно только одинаковые единицы: t_до и t_после относятся к одной и той же полной операции. Время короткой пробы в формулу напрямую не подставляйте: по нему вы оцениваете t_после для полной операции. Полный замер t_после на двух-трёх операциях – в самостоятельной работе, после него раздел 8 пересчитывается (документ 5-6).

Формула:

```
Э_ч   = (t_до − t_после) × N × n × M / 60
Э_руб = (Э_ч − З_ч) × С
```

| Величина | Ваше значение | Откуда взято |
|---|---|---|
| t_до, минут на полную операцию без ИИ | | замер из задания к модулю 5 или оценка по опыту с пометкой «оценка» |
| t_после, минут на ту же полную операцию с ИИ, вместе с проверкой | | на занятии – оценка по результатам пробы с пометкой «оценка»; после занятия – замер на двух-трёх операциях |
| N, операций в месяц на сотрудника | | |
| n, сотрудников, выполняющих операцию | | |
| M, рабочих месяцев в году | | в учебном примере 11; в своей задаче обоснуйте период и не вычитайте отпуска дважды |
| З_ч, часов на подготовку и поддержку в год | | |
| С, стоимость часа | 1200 руб. | условная учебная ставка |
| Э_ч | | |
| Э_руб | | |

Проверьте себя:

- t_после включает проверку?
- t_до и t_после относятся к одной и той же полной операции? Оценки помечены словом «оценка»?
- Минуты переведены в часы делением на 60?
- Период M обоснован, отпуска не учтены дважды?
- Затраты на подготовку и поддержку вычтены?
- В выводе написано «освобождается N часов в год», а не «можно сократить сотрудников»?

Если эффект получился меньше затрат или близким к нулю, так и напишите. Сценарий можно оставить как личный приём, если он повышает качество, или отказаться от него. Честный отрицательный результат засчитывается.

**Результат:** раздел 8 паспорта.

## Задание 4. Представить сценарий группе (55 мин)

Каждый слушатель рассказывает о своём сценарии. Время на одного: 55 минут, делённые на число выступающих. При группе до 10 человек – около 5 минут: 3 минуты рассказ, 2 минуты вопросы. Если участников больше, преподаватель распределяет их по двум комнатам ВКС; обсуждения идут одновременно, а он переходит между комнатами.

План выступления:

1. Задача и как часто она встречается.
2. Сервис и маршрут данных.
3. Что показала проба: что получилось, что пришлось исправить.
4. Экономия в часах в год – предварительная оценка, что в ней замерено, а что оценено.
5. Что дальше: личный приём, служба или предложение на автоматизацию.

Слушатели и преподаватель отвечают по листу обратной связи:

| Вопрос | Да / нет / комментарий |
|---|---|
| Задача одна и описана конкретно | |
| Сервис разрешён для уровня данных задачи (таблица темы 2.1, правила организации) | |
| Проверка конкретная: что, чем, кто, сколько минут | |
| Время «после» включает проверку | |
| Ограничения названы | |
| Расчёт эффекта сходится | |
| Понятно, кто принимает результат | |

Запишите замечания к своему паспорту: их нужно учесть при доработке для итоговой аттестации.

**Результат:** список замечаний к паспорту.

## Итоги курса (15 мин)

Преподаватель подводит итоги пяти дней, показывает, как сдавать итоговую аттестацию на Платформе: паспорт сценария и тест. Вопросы по аттестации.

## Дополнительно, для тех, кто уже работает с ИИ

1. **Цепочка вместо одного запроса.** Если ваш сценарий сейчас – один запрос, разбейте его на два-три шага и сравните на тех же примерах: стало ли проще проверять?
2. **Контрольный набор для сценария.** Подготовьте 5–10 примеров с заранее известным правильным результатом, в том числе один с подвохом (противоречивые данные или посторонняя строка-команда в тексте). Прогоните сценарий и запишите, сколько примеров прошло. Такой набор нужен, чтобы перепроверять сценарий после смены модели или сервиса.
3. **Черновик предложения на автоматизацию.** Если эффект получился заметным, составьте одностраничное предложение: паспорт кратко, результат пробы, замер времени, расчёт эффекта, что нужно от ИТ и подразделения по защите информации. Порядок подачи предложений уточните в своей организации.
