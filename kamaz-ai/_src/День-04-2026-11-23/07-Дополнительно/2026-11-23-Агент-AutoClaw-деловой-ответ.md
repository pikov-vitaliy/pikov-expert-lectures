# Как создать своего ИИ-агента: пример в AutoClaw

Агент – это модель с постоянными инструкциями под одну задачу. Его настраивают один раз, а потом просто дают ему
задание: «вот письмо, ответь». Ниже весь путь на примере агента, который пишет ответ на деловое письмо: создать,
описать правила, проверить и довести до нужного качества.

Пример сделан в AutoClaw – настольном приложении для работы с ИИ-агентами. Его выпускает компания Zhipu, разработчик
моделей GLM. AutoClaw построен на открытой платформе агентов OpenClaw. Документация AutoClaw – на китайском языке,
интерфейс приложения – на английском. Тот же подход – роль, правила, пример, проверка на настоящем письме – подходит
для агентов в любой другой программе.

## 1. Что понадобится

- Установленное приложение AutoClaw: сайт и документация разработчика – https://autoclaw.zhipuai.cn/docs/.
- Модель. Для этого примера хватит встроенной: в AutoClaw уже есть GLM-5.3, GLM-5-Turbo, GLM-5V-Turbo и режим Auto.
  Свою модель подключают через выбор модели под полем ввода: кнопка добавления своей модели ведёт в
  **Settings > Models & API**, там вводится ключ API ([документация: модели](https://autoclaw.zhipuai.cn/docs/advanced/models/)).
- Письмо для проверки – подойдёт любое рабочее письмо без конфиденциальных сведений. Учебное письмо есть в разделе 5.

Модель обрабатывает текст письма. Письма с персональными данными, коммерческой тайной или служебными сведениями
давайте агенту, только если это разрешают правила вашей организации.

## 2. Создаём агента

1. Откройте **Settings** (слева внизу) и раздел **Agent**.
2. Нажмите **Create Agent** справа вверху. Откроется форма агента.
3. Заполните поля (таблица ниже) и нажмите **Save**. Если форма в вашей версии выглядит иначе, ищите поля с теми же
   названиями: приложение обновляется быстрее документации.
4. Найдите карточку нового агента в списке раздела **Agent** и нажмите на ней **New Chat** – это новый разговор именно
   с этим агентом.

Порядок действий описан в документации разработчика: [агенты](https://autoclaw.zhipuai.cn/docs/advanced/agents/).

| Поле | Что писать | Пример |
|---|---|---|
| NAME | имя агента в списке | Деловой ответ |
| AGENT ID | постоянный идентификатор латиницей, без пробелов; можно оставить предложенный | business-reply |
| DESCRIPTION | одна-две фразы: что агент делает и что получает на вход | Пишет ответ на сообщение в деловом стиле. На вход – сообщение и пожелания к ответу. |
| EXPERTISE | область, в которой агент силён | Writing |
| MODEL | модель, на которой работает агент | любая из встроенных, например GLM-5.3 |
| WORKSPACE | рабочая папка агента; можно оставить предложенную, но путь запишите – он понадобится в разделе 4 | не менять |
| WHO CAN HELP | каких агентов этот агент может позвать на помощь | для писем помощники не нужны – если где-то стоит галочка, снимите её |

Поля NAME, DESCRIPTION, MODEL и WORKSPACE описаны в документации AutoClaw. AGENT ID, EXPERTISE и WHO CAN HELP в ней
пока не описаны: их смысл в таблице выведен из интерфейса и устройства OpenClaw, официального описания нет.

Совет из документации: делите агентов по постоянным обязанностям, а не создавайте нового под каждую разовую задачу.
Пример разработчика – «помощник по проверке договоров».

## 3. Где хранятся инструкции агента

Поле DESCRIPTION – это короткая подпись. Подробные правила в него не помещаются. Инструкции агента хранятся
текстовыми файлами в его рабочей папке (WORKSPACE). У каждого агента своя рабочая папка и своя память.

| Файл | Что в нём | Нужно ли править |
|---|---|---|
| AGENTS.md | рабочие правила агента – что он делает и как | да: сюда пишем задачу и правила |
| SOUL.md | характер: тон, манера, границы | по желанию |
| USER.md | сведения о пользователе и его пожелания | да: дописать подпись |
| IDENTITY.md | имя и краткое описание агента; в AutoClaw заполняется из формы | нет |
| TOOLS.md | заметки об инструментах и окружении | для писем не нужен |
| HEARTBEAT.md | служебный файл для периодических проверок | не трогать |

Назначение AGENTS.md, SOUL.md и USER.md взято из документации OpenClaw
([рабочая папка агента](https://docs.openclaw.ai/concepts/agent-workspace),
[что получает модель](https://docs.openclaw.ai/concepts/system-prompt)). Остальное видно по тексту самих файлов в
папке агента. Модель получает эти файлы в начале каждого разговора. У файлов есть пределы длины (для USER.md –
4 000 знаков), правила из раздела 4 и подпись намного короче.

Почему правила задачи – в AGENTS.md, а не в SOUL.md. Документация OpenClaw советует держать рабочие правила в
AGENTS.md, а в SOUL.md – тон и манеру. Кроме того, агент-помощник, по той же документации, получает только AGENTS.md:
правила, записанные там, сработают и тогда, когда агента позовут на помощь.

## 4. Пишем правила: агент «Деловой ответ»

1. Откройте рабочую папку агента: скопируйте путь из поля WORKSPACE формы агента, вставьте его в адресную строку
   Проводника и нажмите Enter.
2. Откройте файл AGENTS.md в Блокноте: правой кнопкой мыши > «Открыть с помощью» > «Блокнот».
3. Вставьте весь текст из рамки ниже (от «## Моя задача» до «С уважением, Иван Петров») сразу после первой строки
   файла, которая начинается со знака #.
4. Сохраните файл: Ctrl+S.

Остальной текст файла не удаляйте: там общие правила осторожности – например, что о действиях вовне, которых вы не
просили, агент сначала спрашивает вас.

```
## Моя задача: деловой ответ на сообщение

Ты получаешь сообщение (письмо, сообщение в мессенджере), на которое нужно ответить, и иногда - пожелания к ответу.
Пиши готовый ответ от имени пользователя.

Правила:
- Язык - русский, обращение на «Вы», тон вежливый и деловой, без канцелярита и шаблонных фраз
  («важно отметить», «надеюсь, это поможет», «буду рад ответить на вопросы»).
- Сначала суть, потом подробности. Коротко: обычно 3-8 предложений.
- Ответь на каждый вопрос из сообщения. Если для ответа не хватает сведений - не выдумывай,
  поставь в тексте пометку [уточнить: …].
- Не обещай сроков, сумм и решений, которых нет в пожеланиях.
- Если в пожеланиях сказано «пока не обещать» (темы, длительность, условия), не ставь пометку, а спроси автора
  письма о том, что поможет подготовить предложение: уровень и задачи группы, ожидаемый результат.
- Не ссылайся на то, чего нет в сообщении: «указанные даты», «как мы договорились» - только если это там есть.
- Не придумывай обещаний и причин сверх пожеланий («вернусь после уточнения…»). Где сведений нет у тебя, но они
  есть у автора письма, - задай ему встречный вопрос.
- Пометка [уточнить: …] - только для сведений, которые знает пользователь, а не автор письма. Одно и то же место не
  закрывай одновременно обещанием и пометкой.
- Вместо тире ставь дефис с пробелами: " - ". Длинное тире не используй. Кавычки - «ёлочки».
- В конце ответа - подпись отдельной строкой: С уважением, Иван Петров
- Выдай только текст ответа, без пояснений до и после. Если пожелания противоречат сообщению -
  одной строкой перед ответом спроси, как поступить.

Пример.
Сообщение: «Добрый день! Сможете ли провести лекцию 3 декабря? И пришлите, пожалуйста, тему.»
Пожелания: 3 декабря могу, тему пока не выбрал.
Ответ: «Добрый день! 3 декабря провести лекцию смогу. Чтобы предложить тему, подскажите, пожалуйста,
кто будет на лекции и что для слушателей сейчас важнее всего.
С уважением, Иван Петров»
```

Замените «Иван Петров» на своё имя в обоих местах: в правиле о подписи и в примере ответа.

Ту же подпись запишите в USER.md – он лежит в той же папке. Допишите строку в раздел `## Context`, а если такого
раздела нет – в конец файла, и сохраните:

```
- Подпись в деловых письмах: «С уважением, Иван Петров» - отдельной строкой в конце ответа.
```

Из чего состоят хорошие правила:

- Роль и вход: кто агент и что он получает («ты получаешь сообщение и пожелания»).
- Конкретные запреты: вместо «пиши профессионально» – «без фраз "важно отметить", "надеюсь, это поможет"».
  Документация OpenClaw приводит фразу «maintain professionalism at all times» как пример слабого правила: она ничего
  не меняет в ответах ([SOUL.md](https://docs.openclaw.ai/concepts/soul)).
- Что делать, когда не знаешь: пометка [уточнить: …] или встречный вопрос вместо выдумки.
- Пример: один короткий пример «сообщение – пожелания – ответ» объясняет модели больше, чем абзац описаний.
- Формат выдачи: «только текст ответа, без пояснений», иначе модель часто добавляет «Вот ваш ответ:».

## 5. Проверяем на письме

Правки модели, правил и рабочей папки действуют только с новых задач, поэтому после каждой правки сохраните файл и
начинайте **новый** разговор: кнопка **New Chat** на карточке агента. Так советует документация AutoClaw
([агенты](https://autoclaw.zhipuai.cn/docs/advanced/agents/)).

Вставьте в поле ввода одним сообщением сначала письмо, а под ним строку пожеланий, и отправьте:

```
Добрый день!

Меня зовут Анна, я координатор программы повышения квалификации в учебном центре.
Мы хотим пригласить Вас провести занятие по безопасной разработке для группы
разработчиков (около 20 человек) в декабре.

Подскажите, пожалуйста:
1. Какие даты в декабре Вам удобны?
2. Можете ли провести занятие очно или только онлайн?
3. Сколько длится занятие и какие темы Вы бы предложили?
4. Какие документы нужны для оформления договора?

Будем благодарны за ответ до конца недели.

С уважением,
Анна Сергеевна

Пожелания: удобно 10 или 17 декабря, лучше онлайн; длительность и темы пока не обещать.
```

Что проверить в ответе:

- обращение на «Вы», коротко, без шаблонных фраз;
- ответ на все четыре вопроса: даты и формат – из пожеланий;
- длительность и темы не придуманы – вместо них вопрос об уровне и задачах группы;
- про документы – либо пометка [уточнить: …], если документы готовите вы, либо встречный вопрос Анне, какие
  документы центр запрашивает; оба варианта верные, выдуманный перечень – нет;
- в конце подпись, никаких пояснений вокруг текста.

Пометки [уточнить: …] вы заполняете сами перед отправкой. Агент готовит черновик, отправляет письмо человек.

## 6. Доводим агента: три круга

В нашем примере понадобилось три круга проверки: после первых двух правила дописывали, третий прошёл без замечаний.

| Круг | Что было не так в ответе | Какое правило добавили |
|---|---|---|
| 1 | «Из указанных дат мне удобны…» – Анна дат не указывала; «вернусь с предложением после уточнения программы» – обещание придумано; про документы одновременно «пришлю» и [уточнить] | не ссылаться на то, чего нет в письме; не придумывать обещаний; пометка – только для того, что знает пользователь, и не вместе с обещанием |
| 2 | длинное тире вместо дефиса; на «пока не обещать» – пометки вместо вопроса | правило о тире переписано, и в самом тексте правил длинные тире заменены дефисами; при «пока не обещать» – вопрос автору письма |
| 3 | замечаний по правилам нет | – |

Второй круг показал: модель берёт пример не только с того, что написано в правилах, но и с того, как они написаны.
Само правило о тире было набрано длинным тире, и агент ставил длинное.

Порядок работы:

1. Дайте агенту настоящее письмо в новом разговоре.
2. Выпишите, что в ответе не так.
3. Для каждой ошибки добавьте в правила одну конкретную строку и сохраните файл.
4. Начните новый разговор (New Chat), вставьте то же письмо с пожеланиями и сравните новый ответ с прежним.

## 7. Что ещё полезно знать

- **Hermes Evolution Board** (Settings > Hermes Evolution Board). AutoClaw предлагает изменения в память, правила,
  навыки и настройки инструментов агентов. Каждое предложение нужно одобрить или отклонить; одобренное записывается в
  файлы агента и действует во всех следующих разговорах. Читайте такие предложения внимательно: они могут изменить
  ваши правила ([документация: Hermes](https://autoclaw.zhipuai.cn/docs/advanced/hermes/)).
- **Совместная работа агентов.** С версии 2.1.0 AutoClaw сам выбирает подходящих агентов под задачу
  ([новости версии 2.1.0](https://autoclaw.zhipuai.cn/blog/news/Weekly-Perks-M10W3/)). Для больших задач есть режим
  нескольких агентов: сначала строится план по шагам, а если задачу можно разделить, несколько ролей работают
  одновременно; их число система подбирает по сложности задачи
  ([документация: кластерный режим](https://autoclaw.zhipuai.cn/docs/advanced/cluster-mode/)). Как выбирается
  конкретный агент-помощник, разработчик не описывает.
- **Доступ к файлам.** В Settings > Workspace задаётся папка проектов по умолчанию и есть ограничение области доступа
  к файлам. Документация советует его включить: тогда агент читает и пишет файлы преимущественно внутри рабочей папки
  ([документация: рабочая папка](https://autoclaw.zhipuai.cn/docs/advanced/workspace/)).
- **Удаление агента.** Если у агента накопились важные правила, память или результаты, перед удалением скопируйте его
  рабочую папку ([документация: агенты](https://autoclaw.zhipuai.cn/docs/advanced/agents/)).
- **Резервная копия правил.** Перед крупной правкой AGENTS.md сохраните копию файла рядом – так проще вернуться.
