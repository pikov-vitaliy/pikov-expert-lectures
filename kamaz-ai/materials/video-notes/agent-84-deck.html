01

Агент и чат-бот

Чем агент отличается от чата и как модель, умеющая только писать текст, что-то делает.

Мозг без рук

Модель продолжает текст. Агенту дают инструменты и цикл

Модель сама по себе

  • Получает текст, предсказывает следующее слово
  • Не видит часов, файлов и сети
  • Знает мир на дату конца обучения

Агент

  • Та же модель + инструменты: поиск, команды, файлы, почта, браузер
  • Работает в цикле: подумал, сделал, посмотрел на результат
  • Сам выбирает следующий шаг

Определение, которое приводит автор: агент – модель, вызывающая инструменты в цикле ради цели (С. Уиллисон).

Облако или дома

И гибрид: тот же агент с другим адресом сервера

Облако

  • Самые сильные модели, высокая скорость
  • Оплата каждого токена: 2 млн входных у Opus 5.5 – 8 долларов, по словам автора
  • Файлы и команды уходят на чужой сервер; часть сервисов официально не работает в России

Дома

  • Данные не покидают компьютер, счёта нет, сеть не нужна
  • Нужна видеокарта, модели слабее
  • Разрыв сокращается: по данным разработчиков, Qwen3.6-27B – 77,2 % на SWE-bench Verified против 63,7 % у Claude 3.7 Sonnet в феврале 2025

Гибрид: агент автора говорит с моделью на языке API OpenAI; его понимают llama.cpp, Ollama, LM Studio и почти все облака. По словам автора, достаточно сменить адрес; в опубликованном скрипте это три строки: URL, KEY и MODEL.

Цикл агента в коде

Функция agent() из файла agent.py – 24 строки без изменений

def agent(task, max_steps=15):
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": task}]
    for step in range(1, max_steps + 1):
        reply = requests.post(URL, headers={"Authorization": f"Bearer {KEY}"}, timeout=600,
                              json={"model": MODEL, "messages": messages, "tools": TOOLS}).json()
        msg = reply["choices"][0]["message"]
        calls = msg.get("tool_calls") or []
        if msg.get("reasoning_content"):
            print(f"[{step}] мысль: {msg['reasoning_content'].strip()[:200]}")
        messages.append({"role": "assistant", "content": msg.get("content") or "",
                         **({"tool_calls": calls} if calls else {})})
        if not calls:  # инструменты больше не нужны — это ответ
            return msg.get("content")
        for call in calls:
            name = call["function"]["name"]
            print(f"[{step}] действие: {name} {call['function']['arguments']}")
            try:
                args = json.loads(call["function"]["arguments"] or "{}")
                result = FUNCS[name](**args)
            except Exception as e:  # ошибка — тоже наблюдение: модель увидит её и исправится
                result = f"Ошибка: {e!r}"
            print(f"[{step}] результат: {result[:300]}")
            messages.append({"role": "tool", "tool_call_id": call.get("id", str(step)), "content": result})
    return "Стоп: закончился лимит шагов."

Первый запуск: две ловушки

Задача та же: видеокарта, модели на дисках, отчёт

Что сделал агент

  • Сразу три независимые команды: видеокарта, диск D, кэш Hugging Face
  • Заметил нулевые размеры, выяснил, что это ссылки, посчитал настоящие файлы
  • Windows показала 4 ГБ видеопамяти – перепроверил через nvidia-smi: 24

Чем закончилось

  • Перечитал отчёт; кракозябры в консоли проверил по файлу – кодировка в порядке
  • 10 шагов, меньше двух минут, верный отчёт
  • Ловушки не подстроены – так устроен компьютер автора

Разрешения в этом прогоне выдавал скрипт: пропускал только команды без изменений, записать можно было только отчёт.

Важно не только «может ли», но и «всегда ли».
Горизонт 12 часов – при успехе в половине случаев; при 8 из 10, по словам автора, около полутора часов.

Пример автора: 0,95 в двадцатой степени ≈ 0,36 – если шаги ошибаются независимо друг от друга. По словам автора, у METR минимум 16 % «успехов» на задачах дольше 8 часов – это обман проверки, а не решение.
