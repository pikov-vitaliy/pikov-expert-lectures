# Материалы занятия

Курс «Специалист по процессам разработки безопасного программного обеспечения».

Тема дня: **история и классификация языков, shift-left, компоненты программного стека и безопасная работа с SQL на примере реестра компонентов.**

День состоит из двух лекций по 90 минут и трёх практических занятий по 90 минут. Все практические данные вымышлены.

## С чего начать

1. Откройте `index.html` в браузере — это основная лекция дня.
2. Прочитайте `materials/konspekt.md` — текстовый конспект двух лекционных блоков.
3. Работайте по `materials/praktikum.md` — три последовательных практических блока.
4. Перейдите в `code/` и выполняйте команды только в указанном порядке.
5. В самостоятельной части изменяйте только `code/step3_student.py`.

## Что требуется

- Windows PowerShell;
- Python 3.11 или новее;
- встроенный модуль Python `sqlite3`;
- SQLite с поддержкой таблиц `STRICT`;
- текстовый редактор или IDE.

Сторонние пакеты и доступ в интернет для выполнения практикума не нужны. Интернет требуется только для перехода к внешним нормативным и методическим источникам.

Проверьте окружение:

```powershell
py --version
py -c "import sqlite3; print(sqlite3.sqlite_version)"
```

Первая команда должна показать Python 3.11 или новее. Вторая печатает версию встроенного SQLite, например `3.45.3`; нужна версия 3.37.0 или новее. Сравнивайте числа по частям: у `3.45.3` вторая часть — 45, это больше 37, версия подходит; у `3.35.5` вторая часть — 35, это меньше 37, версия не подходит. На версии ниже 3.37.0 таблицы `STRICT` не создадутся: `step1_schema.py` завершится ошибкой `near "STRICT": syntax error`. Решение — установить Python 3.11 или новее: вместе с ним обновится и встроенный SQLite.

## Если Python ещё не установлен

1. Скачайте установщик с официальной страницы [https://www.python.org/downloads/](https://www.python.org/downloads/) — нужна версия 3.11 или новее.
2. Современный установщик — Python Install Manager (Python 3.14 и новее) — сам устанавливает команды `py`, `python` и `pymanager`, дополнительных действий не требуется. Если вы скачали классический установщик Python 3.11–3.13, обязательно отметьте галочку **«Add python.exe to PATH»** на первом экране установщика.
3. Закройте и снова откройте PowerShell, затем проверьте:

```powershell
py --version
```

> [!warning] ⚠️ Старые версии из Microsoft Store не подходят без оговорок
> У старых пакетов Python из Microsoft Store (3.13 и старше) нет лаунчера `py`, на котором построены все команды комплекта. Начиная с Python 3.14 через Microsoft Store распространяется Python Install Manager, который устанавливает и `py`, и `python`. Если старый Store-Python уже установлен и переустановить его не получается, заменяйте `py` на `python` в каждой команде: например, `python .\step1_schema.py` вместо `py .\step1_schema.py`.

## Как увидеть разницу между красным и зелёным прогоном

Публичный архив предназначен и для самостоятельного повторения, поэтому в нём
есть `step3_student_solution.py`. Открывайте готовое решение только **после собственной попытки**: сначала сохраните исходный RED, реализуйте функции и
зафиксируйте собственный результат. Для оцениваемого занятия преподаватель
выдаёт комплект без файла решения до завершения задания.

По умолчанию `test_student.py` проверяет ваш рабочий файл `step3_student.py`.
В комплекте есть два дополнительных файла, которые можно подключить к тем же
тестам, не изменяя `test_student.py`:

| Файл | Назначение |
|---|---|
| `step3_student.py` | Ваш рабочий файл (красный до выполнения, зелёный после) |
| `step3_student_template.py` | Заглушки с закомментированными подсказками |
| `step3_student_solution.py` | Готовое решение (всегда зелёное) |

Тесты умеют переключаться между модулями через переменную окружения
`REGISTRY_MODULE`. Это штатный механизм, встроенный в `test_student.py` —
менять сам файл тестов не нужно.

### Windows (PowerShell)

```powershell
# Прогнать тесты против готового решения (должен быть зелёный):
$env:REGISTRY_MODULE="step3_student_solution"
py -m unittest -v test_student.py

# Вернуться к своему рабочему файлу:
Remove-Item Env:\REGISTRY_MODULE
py -m unittest -v test_student.py

# Или одной командой (временная переменная только на этот запуск):
cmd /c "set REGISTRY_MODULE=step3_student_solution && py -m unittest -v test_student.py"
```

> [!warning] ⚠️ Не забывайте сбрасывать переменную
> Если `$env:REGISTRY_MODULE` осталась в сессии, тесты будут молча
> проверять не тот файл. Проверьте: `$env:REGISTRY_MODULE` — если
> вывод не пустой, удалите: `Remove-Item Env:\REGISTRY_MODULE`.

## Важные предупреждения

> [!warning] ⚠️ `demo_unsafe_query.py` намеренно уязвим
> Файл нужен только для локальной демонстрации CWE-89 на фиксированной строке и базе в памяти. Не копируйте функцию небезопасного поиска в рабочий код и не подключайте демонстрацию к реальным данным.

> [!important] ❗ Не меняйте критерии приёмки
> В самостоятельной части редактируйте только `step3_student.py`. Не изменяйте `test_student.py`, `schema.sql` и `seed.sql`, иначе зелёный результат не будет независимым свидетельством.

> [!note] ✏️ Повторный запуск шага 1
> `step1_schema.py` не перезаписывает существующую базу. Если `components.db` уже создана, укажите новое имя:
>
> ```powershell
> py .\step1_schema.py components-02.db
> ```

> [!note] ✏️ Учебный реестр не равен промышленной SCA/SBOM-системе
> Практикум показывает ограничения целостности, безопасные запросы, транзакции, аудит и минимальные полномочия. Он не выполняет автоматическое обнаружение зависимостей, проверку происхождения, поиск уязвимостей или лицензионное заключение.
