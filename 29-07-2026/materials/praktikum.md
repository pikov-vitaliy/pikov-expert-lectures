Практикум состоит из трёх последовательных блоков по 90 минут. Вы пройдёте путь от схемы данных до самостоятельной реализации защищённого API.

**Сквозной результат:** рабочий учебный реестр компонентов, в котором ограничения данных заданы на уровне схемы, значения отделены от SQL-команд, динамические идентификаторы ограничены allowlist, связанные изменения атомарны, а чтение может выполняться с минимальными полномочиями.

В этом файле нет готового решения `step3_student.py`. Критерии поведения открыты, чтобы результат можно было проверить, но выбор конструкции и написание кода остаются за вами.

## Правила безопасной работы

1. Используйте только вымышленные учебные данные из комплекта.
2. Не вводите реальные пароли, токены, персональные данные и сведения о компонентах закрытого продукта.
3. `demo_unsafe_query.py` намеренно содержит уязвимый шаблон. Запускайте его только как локальную демонстрацию и не переносите код из него в проекты.
4. В самостоятельной части изменяйте только `step3_student.py`.
5. Не изменяйте `schema.sql`, `seed.sql` и `test_student.py`: иначе результат тестирования перестанет быть независимым свидетельством.
6. Не удаляйте существующую базу автоматически. `step1_schema.py` не перезаписывает файл; для повторного запуска выберите другое имя.

## Шаг 3.2. Изучите контракт

Откройте:

```powershell
Get-Content .\step3_student.py
Get-Content .\test_student.py
```

Реализовать нужно пять операций.

### `add_component`

Контракт:

- сохранить все переданные поля;
- вернуть идентификатор добавленной записи;
- отвергнуть пустое имя до выполнения SQL;
- отвергнуть неизвестную критичность;
- воспринимать SQL-подобную строку имени как обычные данные.

### `search_components`

Контракт:

- выполнять регистронезависимый поиск по фрагменту имени;
- не интерпретировать SQL-подобный текст как команду;
- воспринимать `%` в поисковом терме как обычный символ;
- ограничивать допустимое значение `limit`.

### `list_components`

Контракт:

- сортировать только по явно разрешённым столбцам;
- отвергать неизвестный или SQL-подобный идентификатор сортировки;
- не изменять данные при ошибочном вводе.

### `change_license`

Контракт:

- изменить лицензию существующего компонента;
- записать связанное событие аудита;
- выполнить обе записи атомарно;
- при отсутствии компонента не оставлять событие аудита.

### `open_read_only`

Контракт:

- открыть существующую базу для чтения;
- позволить выполнить `SELECT`;
- не позволить изменить данные через это соединение.
