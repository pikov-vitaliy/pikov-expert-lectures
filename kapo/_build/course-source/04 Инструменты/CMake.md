# CMake

> [!info] Контекст
> CMake — не пакетный менеджер, а генератор сборочных систем: из `CMakeLists.txt` он создаёт нативные сборочные файлы (Ninja, Make, проекты Visual Studio). Для SCA это означает, что CMake описывает *намерение* слинковать цели и найти библиотеки, но сам по себе не гарантирует ни версию, ни факт линковки.

## Для чего
CMake разрешает, какие библиотеки нужны цели (`find_package`, `target_link_libraries`), куда смотреть за заголовками, и каким компилятором собирать. В контексте инвентаризации C/C++ он ценен как источник *декларации* зависимостей и как точка, где можно снять граф целей и перехватить реальные вызовы компилятора (через `compile_commands.json`).

## Как применяют
Граф зависимостей целей в формате Graphviz:
```bash
cmake -S . -B build --graphviz=deps.dot
dot -Tsvg deps.dot -o deps.svg
```
База реальных команд компиляции (вход для build‑scan и cdxgen):
```bash
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON   # → build/compile_commands.json
```
Машинная модель проекта через CMake File API (каталог‑запрос `.cmake/api/v1/query/`) отдаёт JSON с целями, ссылками и путями к библиотекам — это надёжнее, чем парсить `CMakeLists.txt` глазами.

## Сильные стороны
- `compile_commands.json` — точный список того, что и с какими `-I/-L/-l` компилируется; основа для перехвата реальных, а не задекларированных зависимостей.
- File API и `--graphviz` дают машинную модель графа целей без запуска самой сборки до конца.
- `find_package` помечает, какие компоненты ищутся как внешние, — отправная точка для разметки.

## Ограничения
- `find_package(OpenSSL)` находит то, что лежит в системе, и не фиксирует версию — на другой машине подтянется другая. Lockfile отсутствует как класс.
- `FetchContent`/`ExternalProject` затягивают исходники по URL/commit в обход любого пакетного менеджера — их легко упустить при инвентаризации.
- Декларация ≠ факт: цель может быть объявлена, но статически вшита или, наоборот, не слинкована. Реальный состав даёт только анализ артефакта.

## Offline / on-premise
Да. CMake — локальный инструмент без сетевых зависимостей. Сетевые риски вносят не сам CMake, а вызовы `FetchContent_Declare(... GIT_REPOSITORY ...)`/`ExternalProject`, тянущие код из интернета во время конфигурации; в закрытом контуре их перенаправляют на внутренние зеркала или заменяют vendored‑исходниками.
