# Чек-лист качества SPDX

## Назначение
Покомпонентная проверка качества SBOM в формате SPDX (ISO/IEC 5962): корректность идентификаторов `SPDXID`, namespace документа, секции `relationships`, разделение `LicenseConcluded` / `LicenseDeclared` и наличие `PackageVerificationCode`. Проверяет, пригоден ли SPDX-документ как доказательная опись поставки.

## Когда применяется
После приёмки конверта ([[Чек-лист ZIP поставки]]), когда соисполнитель поставляет SBOM в SPDX (а не CycloneDX). Применяется к каждому файлу `*.spdx.json` / `*.spdx` поставки.

> [!info] Контекст формата
> SPDX — документо-ориентированный формат с явной моделью отношений: пакеты (`packages`), файлы (`files`) и связи (`relationships`) между ними. Лицензионная модель богаче CycloneDX за счёт разделения «объявлено/заключено». Форматные детали — [[05 Нормативка/SPDX ISO IEC 5962]].

## Блок 1. Заголовок документа
- [ ] `spdxVersion` указан и поддерживается (SPDX-2.2/2.3).
- [ ] `dataLicense` = `CC0-1.0` (требование спецификации).
- [ ] `SPDXID` документа = `SPDXRef-DOCUMENT`.
- [ ] `documentNamespace` присутствует, является уникальным URI (не переиспользуется между поставками).
- [ ] `creationInfo` содержит `creators` (инструмент + роль/организация, без ФИО) и `created` (timestamp).

## Блок 2. Пакеты и идентификаторы
- [ ] У каждого пакета задан уникальный `SPDXID` вида `SPDXRef-...`.
- [ ] Заполнены `name` и `versionInfo`.
- [ ] `downloadLocation` задан (или явно `NOASSERTION` с обоснованием).
- [ ] `externalRefs` содержат `purl` (PACKAGE-MANAGER) и, где применимо, `cpe23Type` (SECURITY) — для сопоставления с уязвимостями.
- [ ] `PackageVerificationCode` присутствует для пакетов с файлами (контроль целостности содержимого).

## Блок 3. Отношения (relationships)
- [ ] Присутствует `DESCRIBES` от `SPDXRef-DOCUMENT` к корневому пакету продукта.
- [ ] Зависимости выражены `DEPENDS_ON` / `CONTAINS` (граф не плоский список без связей).
- [ ] Все `relationships` ссылаются на существующие `SPDXID` (нет «висячих» ссылок).
- [ ] Для C/C++ граф согласован с build evidence поставки (см. [[П20. CMake dependency graph]]).

## Блок 4. Лицензии
- [ ] У пакетов заполнены оба поля: `licenseConcluded` и `licenseDeclared`.
- [ ] Расхождения `Concluded` ≠ `Declared` отмечены и идут в юридический разбор (см. [[П27. Юридическое заключение и реестр лицензий]]).
- [ ] Лицензионные выражения валидны (SPDX License Expression); `NOASSERTION` не используется как «заглушка по умолчанию».
- [ ] При наличии — `licenseInfoInFiles` не противоречит `licenseConcluded` пакета.
