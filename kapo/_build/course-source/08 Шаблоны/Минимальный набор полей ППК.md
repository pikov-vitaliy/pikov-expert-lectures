# Минимальный набор полей ППК

## Назначение
Спецификация обязательных полей записи перечня программных компонентов (ППК) — долговечного учётного слоя Организации, дедуплицированного по `purl`. Задаёт минимум, без которого компонент не считается учтённым: координаты, лицензия, владелец, статусы. Это эталон полей, а не заполненная карточка.

## Когда применяется
При проектировании структуры ППК и при приёмке: каждая запись ППК (и каждый SBOM-компонент, попадающий в ППК) проверяется на наличие этих полей. Опирается на минимальные элементы SBOM (см. [[05 Нормативка/NTIA Minimum Elements for SBOM]], [[05 Нормативка/CISA Minimum Elements for SBOM]]).

> [!info] ППК ≠ SBOM
> SBOM — одноразовый снимок сборки. ППК — долговечный реестр Организации: дедупликация по `purl`, владельцы, юридические вердикты, статусы уязвимостей, история решений (см. [[01 Курс/М02 SBOM и ППК как машинный источник фактов/00 Карта модуля|М02]]). Минимум ниже шире минимума SBOM на учётный слой.

## Обязательные поля
| Поле | Обязательно | Источник | Назначение |
|---|---|---|---|
| `purl` (ключ дедупликации) | да | SBOM / порядок идентификации | уникальный учётный ключ |
| Имя компонента | да | SBOM | человекочитаемая идентификация |
| Версия | да | SBOM | точная, не диапазон |
| `cpe` / alias | где применимо | alias worklist | сопоставление с уязвимостями |
| Поставщик/апстрим | да | SBOM / паспорт | происхождение |
| Лицензия (declared) | да | license scan | юридический вход |
| Лицензия (concluded) | да | юр. заключение | юридический вердикт |
| Тип линковки | для C/C++ | build evidence | слепые зоны статической линковки |
| Владелец компонента | да | учётная модель | роль/команда, без ФИО |
| Статус уязвимостей | да | портфель/VEX | актуальное состояние |
| Решение/вердикт | да | политика приёмки | разрешён/риск/блок |
| Срок пересмотра | для исключений | реестр исключений | нет бессрочных |
| Ссылка на evidence | да | хранилище | трассируемость |

## Правила минимума
- [ ] Запись без `purl` не попадает в ППК напрямую — идёт в [[Реестр unresolved libraries]].
- [ ] Поля «declared» и «concluded» лицензии заполняются раздельно (несовпадение — сигнал для юриста).
- [ ] Версия — точная; диапазон/`NOASSERTION` недопустимы как финальное значение.
- [ ] Каждое поле-решение трассируемо до evidence и даты поставки.
