# Паспорт риска компонента

## Назначение
Паспорт риска — карточка одной уязвимости в одном компоненте: что нашли, насколько это опасно в продукте, какое решение принято, кто issuer/владелец и когда пересматривать. Это первичный артефакт, на который ссылаются [[Реестр исключений|реестр исключений]] и [[Порядок принятия риска|решение о принятии риска]].

## Когда применяется
- Уязвимость получила VEX-статус `affected` и не закрывается немедленным обновлением.
- Требуется обосновать принятие риска или отклонение severity по применимости (VEX).
- При переоценке открытого риска на дату пересмотра.

## Карточка риска
| Поле | Значение |
|---|---|
| Компонент | имя библиотеки/пакета |
| Версия (PURL) | `pkg:<eco>/<name>@<version>` |
| CVE / БДУ | идентификатор(ы) уязвимости |
| CVSS | базовый вектор и оценка (v3.1/v4.0) |
| Severity | Critical / High / Medium / Low |
| EPSS / KEV | вероятность эксплуатации / наличие в [[CISA KEV]] |
| Применимость (VEX) | affected / not_affected / under_investigation + обоснование |
| Issuer VEX | роль/подразделение, выпустившее решение для версии продукта |
| Сценарий эксплуатации | как достижима в продуктовой конфигурации |
| Решение | устранить / митигировать / риск принят / заменить |
| Компенсирующие меры | контроль, снижающий вероятность/ущерб + evidence |
| Владелец | роль/ответственный (без конкретных ФИО) |
| Срок устранения / пересмотра | дата по SLA или по [[Порядок принятия риска|принятию риска]] |
| Статус | открыт / митигирован / принят риск / закрыт |
| Evidence | ссылки на VDR/VEX из сервиса аудита/вердиктов, SBOM/ППК, build/reachability evidence, upstream advisory/VEX, протокол ретеста |

> [!example] Заполненный фрагмент
> Компонент: `lib-foo`; Версия: `pkg:npm/lib-foo@1.4.2`; CVE: CVE-2025-12345 (БДУ:2025-XXXXX); CVSS: 7.5 (AV:N/AC:L/PR:N/UI:N); Severity: High; Применимость: `affected` — уязвимый парсер вызывается из публичного endpoint; Issuer VEX: Product Security + владелец сервиса; Решение: обновить до 1.4.3; Срок: 2026-07-15; Владелец: дежурный аналитик SCA (роль).

> [!warning] Severity ≠ риск для продукта
> Базовый CVSS считает «в вакууме». Реальный риск корректируется применимостью (VEX), достижимостью кода и эксплуатируемостью (EPSS/KEV). Паспорт обязан показывать оба значения: базовое и контекстное.

## Правила
- Каждое поле либо заполнено, либо явно помечено `unknown` — пустых клеток нет.
- Статус `закрыт` ставится только при наличии evidence ретеста ([[Регламент ретеста после исправления]]).
- При принятии риска паспорт связывается с записью в [[Реестр исключений]] и имеет дату пересмотра.
- Upstream advisory/VEX не переносится автоматически: он прикладывается как evidence, а продуктовый статус утверждается issuer продукта.
