# Политика лицензионной чистоты

## Назначение
Политика задаёт классы допустимых, условно-допустимых и запрещённых лицензий open source компонентов и правила их использования в продуктах Организации. Она отвечает на вопрос «можно ли поставить эту библиотеку с такой лицензией в продукт и на каких условиях».

## Когда применяется
- При вводе нового компонента в [[Требования к controlled repository|controlled repository]].
- При обнаружении изменения лицензии между версиями компонента.
- При формировании юридической части evidence перед релизом или поставкой заказчику.

## Классы лицензий и решения
Классификация выполняется по нормализованному SPDX-выражению из license scan. Двойные/множественные лицензии (`OR`) трактуются по наиболее благоприятному совместимому варианту, `AND` — по самому строгому.

| Класс | Примеры (SPDX) | Решение по умолчанию |
|---|---|---|
| Разрешённые (permissive) | MIT, BSD-2/3-Clause, Apache-2.0, ISC, Zlib | Разрешено без доп. условий |
| Условные слабые copyleft | LGPL-2.1, LGPL-3.0, MPL-2.0, EPL-2.0 | Разрешено при динамической линковке и сохранении уведомлений |
| Сильные copyleft | GPL-2.0, GPL-3.0, AGPL-3.0 | По умолчанию запрещено в проприетарной поставке; только через [[Порядок исключения лицензии|исключение]] |
| Запрещённые / несовместимые | SSPL, BUSL, CC-BY-NC-*, "proprietary, no redistribution" | Блокировано, замена обязательна |
| Неизвестная / не распознана | `NOASSERTION`, пустое поле | Не релизить до отработки [[Порядок работы с неизвестной лицензией]] |

> [!danger] Запрет на AGPL в сетевом сервисе
> AGPL-3.0 в компоненте, обслуживающем внешние запросы, переводит весь сервис под обязательство раскрытия исходного кода. Допускается только с [[Шаблон юридического заключения по лицензии|юридическим заключением]] и одобренным исключением.

## Обязательства, которые всегда соблюдаются
- Сохранять тексты лицензий и copyright-уведомления (NOTICE) в дистрибутиве.
- Для слабого copyleft — обеспечивать возможность замены библиотеки пользователем (динамическая линковка).
- Не смешивать GPL-код со статически линкуемой проприетарной частью без юридической проверки.
- Для C/C++ legacy фиксировать тип линковки (см. [[П23. Статическая линковка как слепая зона]]) — он меняет лицензионные последствия.

## Контроль и evidence
- Полнота: показатель license coverage в SBOM, доля `NOASSERTION` в worklist.
- Каждое отклонение от класса по умолчанию = запись в [[Реестр исключений]] + [[Шаблон юридического заключения по лицензии|юр.заключение]].
- Эталон проверки — [[07 CodeScoring/Матрица соответствия требованиям OSA SCA|матрица соответствия]].
