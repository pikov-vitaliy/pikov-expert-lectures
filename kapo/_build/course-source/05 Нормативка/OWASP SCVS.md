# OWASP SCVS

## О документе
> [!info] Что это
> **OWASP SCVS** (Software Component Verification Standard) — открытый стандарт OWASP, формулирующий **проверяемые требования к управлению компонентами цепочки поставки ПО**. Это самый «прицельный» под SCA/OSA документ группы: он напрямую про инвентаризацию, SBOM, идентификацию компонентов и контроль происхождения. По духу — чек-лист требований с тремя уровнями строгости (L1–L3).

SCVS структурирован по доменам: инвентаризация (V1), SBOM (V2), сборка и среда (V3), управление пакетами (V4), идентификация компонентов (V5), pedigree/provenance (V6). Уровни L1/L2/L3 позволяют наращивать строгость, не переписывая требования.

## Ключевые требования
- **Полная инвентаризация (V1).** Все first-party и third-party компоненты, включая транзитивные зависимости, должны быть известны и учтены.
- **Машиночитаемый SBOM (V2).** SBOM формируется автоматически, в стандартном формате (CycloneDX/SPDX), на каждый релиз, с точностью до версии.
- **Целостность среды сборки (V3).** Сборка воспроизводима, артефакты собираются из контролируемых источников, build-pipeline защищён.
- **Контролируемое управление пакетами (V4).** Зависимости подтягиваются из доверенного репозитория, версии зафиксированы (lockfiles), отсутствует «слепой» подтяг latest.
- **Однозначная идентификация (V5).** Каждый компонент имеет корректный `purl`/`cpe` и проверяемую целостность (хэш/подпись).
- **Происхождение и pedigree (V6).** Известно, откуда компонент получен, и есть подтверждение, что он не был подменён.

## Что считать evidence
> [!example] Артефакты соответствия
> - SBOM на каждый релиз с метрикой покрытия транзитивных зависимостей (домен V1–V2).
> - CI-gate качества SBOM: процент компонентов с валидным `purl`, наличие версий и хэшей (V5).
> - Конфигурация controlled repository / proxy и lockfiles как доказательство V4.
> - Подпись SBOM/артефактов и проверка целостности — доказательство V3/V6.

Матрица трассировки доменов SCVS на контроли и артефакты:

| Домен SCVS | Контроль SCA/OSA | Подтверждающий артефакт |
|---|---|---|
| V1 Инвентаризация | Портфельный учёт всех зависимостей | SBOM с покрытием транзитивных зависимостей |
| V2 SBOM | Автогенерация SBOM на релиз | CycloneDX/SPDX-документ + лог CI |
| V4 Управление пакетами | Controlled repository, lockfiles | Конфигурация proxy, зафиксированные версии |
| V5 Идентификация | `purl`/`cpe` + хэши | Отчёт качества SBOM (доля валидных `purl`) |
| V6 Provenance | Подпись артефактов/SBOM | Provenance-attestation, проверка подписи |
