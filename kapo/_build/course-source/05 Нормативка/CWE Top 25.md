# CWE Top 25

## О документе
Ежегодный список из 25 наиболее опасных классов слабостей ПО, который ведёт MITRE при поддержке CISA (США) на базе таксономии CWE (Common Weakness Enumeration). В отличие от CVE (конкретная уязвимость в конкретном продукте), CWE описывает *тип* дефекта — например, CWE-79 (XSS), CWE-89 (SQL-инъекция), CWE-787 (out-of-bounds write). Рейтинг рассчитывается по данным реальных CVE (частота + серьёзность по CVSS) за период. Для SCA/OSA это не требование к процессу, а словарь для классификации и приоритизации: он переводит поток CVE из сторонних компонентов в понятные инженеру классы дефектов.

## Ключевые требования
- **CWE как общий язык дефектов**: каждая найденная уязвимость должна иметь привязку к CWE-ID, чтобы устранение шло по типу, а не точечно.
- **Цепочка CVE → CWE → устранение**: от конкретной CVE в компоненте к классу слабости и к инженерному паттерну исправления/контроля.
- **Приоритизация по Top 25**: уязвимости, попадающие в наиболее опасные классы (например, CWE-787, CWE-79, CWE-89), получают повышенный приоритет триажа.
- **Связь с C/C++ legacy**: классы памяти (CWE-787, CWE-125, CWE-416, CWE-476) особенно значимы для нативного кода без пакетного менеджера.
- **Не нормирует процесс**: это таксономия и рейтинг, а не набор контролей; обязательность приходит из политики управления уязвимостями.

## Что считать evidence
- Результаты SCA/SAST-сканирования с проставленными CWE-ID по каждому findings; отчёт о распределении находок по классам CWE.
- Карта соответствия CVE → CWE в VDR: для каждой уязвимости компонента указан класс слабости и его место в Top 25.
- Приоритизация триажа с явной отметкой попадания в Top 25 (повышенный приоритет/SLA устранения).
- Для C/C++: перечень находок по классам памяти (CWE-787/125/416/476) с привязкой к build evidence.
- Решения VEX с обоснованием на уровне класса (почему данный класс слабости не эксплуатируем в контексте продукта).
