# План занятия (90 минут)

## Цели занятия
- Слушатель отличает CycloneDX, SPDX и SWID по структуре файла и по назначению.
- Слушатель знает, что по [[05 Нормативка/BSI TR-03183-2 v2.1.0]] форматом SBOM признаются только CycloneDX ≥ 1.6 и SPDX ≥ 3.0.1, а SWID — лишь идентификатор компонента.
- Слушатель умеет найти обязательные по BSI (раздел 5.2.2) поля компонента в обоих форматах и назвать, что теряется при конвертации.
- Слушатель связывает три категории лицензий BSI (original / distribution / effective) с полями форматов.

## Материалы
- Стенд из [[П01. Стенд WSL2 Docker и базовая гигиена]] (CLI, `jq`).
- Два готовых SBOM одного артефакта: CycloneDX 1.6 JSON и SPDX 3.0.1 JSON.
- [[01 Курс/М03 Форматы SBOM CycloneDX, SPDX, SWID/01 Конспект|Конспект М03]], [[Чек-лист качества CycloneDX]], [[Чек-лист качества SPDX]].
- Выдержка обязательных полей из [[05 Нормативка/BSI TR-03183-2 v2.1.0]] (раздел 5.2).

## Демонстрация (опорные команды)
```bash
# CycloneDX 1.6: спецверсия и обязательные поля компонента
jq '.specVersion' bom.cdx.json
jq '.components[0] | {name, version, purl, hashes, licenses}' bom.cdx.json
# SPDX 3.0.1: версия профиля и пакет
jq '.creationInfo.specVersion // ."@graph"[]?.type' bom.spdx.json
```

## Контрольная точка
Слушатель устно отвечает: (1) является ли SWID форматом SBOM по BSI и почему; (2) какие минимальные версии CycloneDX и SPDX требует BSI; (3) одно поле компонента, которое нет нативно ни в одном формате и кодируется через `bsi:component:*`.
