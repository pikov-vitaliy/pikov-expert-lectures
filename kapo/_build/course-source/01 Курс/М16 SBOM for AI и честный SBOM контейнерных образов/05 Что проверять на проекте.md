# Что проверять на проекте

Чек-лист аудитора по двум темам модуля. Цель — поймать разрыв между декларацией и реальностью (для образов) и неполноту AI-кластеров (для AI-поставки).

## Честный SBOM контейнерного образа

- [ ] **Сверка с реальностью.** SBOM образа сверялся не только с декларацией, но и с фактическим содержимым слоёв (`docker save` + разбор tar-ов), а не принят «как есть».
- [ ] **Секреты во всех слоях.** Поиск секретов выполнен по истории слоёв, а не только по финальной ФС; зафиксировано, что `RUN rm` не удаляет файл из нижнего слоя.
- [ ] **Признаки обфускации метаданных.** Проверено наличие пакетных БД (`/var/lib/dpkg/status`, `/lib/apk/db/installed`, `/var/lib/rpm/`); их отсутствие при работающем ПО помечено как red flag, а не как «чистый образ».
- [ ] **«0 уязвимостей» расследуется.** Результат сканера с нулём findings не принимается без объяснения причины (мало пакетов / затёртые метаданные / ПО мимо менеджера).
- [ ] **Спрятанные бинарники.** Проверка на UPX-упаковку и стрип build-info (`go version -m` не читается → флаг для ручного разбора).
- [ ] **«Неисправимое статикой» вынесено явно.** Multi-stage, внешние загрузки в рантайме, сборка из исходников помечены как непокрываемые статическим SBOM и требующие динамики.
- [ ] **Целостность поставки.** Образ и его SBOM подтверждены attestations (in-toto/SLSA, подпись через Sigstore); проверена защита реестра от tag poisoning и подмены коммитов.
- [ ] **Воспроизводимость.** Зафиксированы digest образа, версии инструментов, дата анализа; SBOM пересобирается из тех же входов.

## SBOM for AI (минимальные элементы)

- [ ] **AI-кластеры присутствуют сверх обычного SBOM.** Заполнены кластеры Models и Datasets, а не только дерево пакетов рантайма.
- [ ] **Идентичность и целостность модели.** Есть `Model identifier` (PURL/SWHID/commit) и `Model hash value` именно по **весам**, с указанием алгоритма.
- [ ] **Лицензия модели по типу открытости.** `Model license` различает open weight / open architecture / open data / open training; противоречия (open weight при закрытых данных) подняты.
- [ ] **Lineage и обучение.** Заполнены `Model description` (предшественник, дистилляция, форк) и `Model training properties` (pre-/post-training, RLHF/DPO/PPO).
- [ ] **Provenance и чувствительность датасета.** `Dataset provenance` (источник, способ сбора), `Dataset sensitivity` (PII/copyright/sensitive) и `Dataset license` заполнены; пустой кластер Datasets при используемой модели — блокер приёмки.
- [ ] **Инфраструктура и безопасность.** Учтены Infrastructure (фреймворки, рантайм, при наличии — ссылка на HBOM) и Security Properties (контроли, в т.ч. защита от prompt injection для LLM).

> [!danger] Стоп-условия приёмки
> 1. В слоях образа найден живой секрет, отсутствующий в финальной ФС.
> 2. SBOM/сканер декларирует «чисто», но реальный состав слоёв с этим расходится (обфускация).
> 3. У используемой AI-модели не заполнены `Model license` (тип открытости) или `Dataset provenance` — нельзя оценить legal/security-риск.
