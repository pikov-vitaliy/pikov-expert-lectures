FOSSology

Роль в линейке лицензионных инструментов FOSSology — это человеческий clearing-workflow с ответственным. ScanCode находит лицензию машиной, ORT применяет к ней политику, а FOSSology фиксирует финальное решение человека (concluded license) с автором, датой и историей — audit trail, которого нет ни у детектора, ни у политики.

Для чего

Серверная система лицензионного clearing: загрузка артефакта → прогон агентов-сканеров → ручной review reviewer-ом → утверждённое заключение (concluded license) с аудиторским следом. Здесь машинная находка detected превращается в concluded с подписью и историей правок, пригодную для юридического заключения и распространения.

Как применяют

Веб-сервер; разворачивается одной командой, дальше работа идёт через web UI или REST API:

docker run -d --name fossology -p 8081:80 fossology/fossology
# web UI: http://localhost:8081/repo  (логин по умолчанию fossy / fossy)
# Upload → отметить агенты nomos, monk, ojo, copyright → Jobs → Browse → License (ручной review) → Exports

Автоматизация через REST (токен генерируется в Admin → API tokens):

BASE="http://localhost:8081/repo/api/v1"
curl -s -X POST "$BASE/jobs" -H "Authorization: Bearer $TOKEN" \
  -H "folderId: 1" -H "uploadId: 3" -H "Content-Type: application/json" \
  -d '{"analysis":{"nomos":true,"monk":true,"ojo":true,"copyright":true},
       "decider":{"nomos_monk":true}}'

Агенты ловят разное: nomos — по сигнатурам (широко, но шумно), monk — по точному совпадению с эталонными текстами, ojo вытягивает теги SPDX-License-Identifier. Их расхождение на файле — кандидат на ручной review. Результат виден в SPDX-экспорте полем LicenseConcluded:

FileName: ./parser.c
LicenseConcluded: GPL-2.0-only
LicenseInfoInFile: GPL-2.0-only
LicenseComments: Concluded by reviewer 'auditor' on 2026-06-17, clearing OK.

Сильные стороны

  • Audit trail: каждое concluded-решение несёт автора, дату и историю — именно это отличает юридический вердикт от машинной строки и нужно для доказательной базы.
  • Несколько агентов с разной логикой (nomos/monk/ojo/copyright); их разногласие само подсказывает, какие файлы требуют внимания человека.
  • Bulk-операции и наследование решений: один раз вынесенный вердикт переносится на повторяющиеся файлы между загрузками.
  • Экспорт в SPDX2, ReadMe_OSS, DEP5 — готовые артефакты для поставки и заключения.

Ограничения

  • Тяжелее ScanCode/ORT: это сервер с БД, scheduler и web UI; инициализация при первом запуске занимает минуты, требует сопровождения.
  • Clearing — ручной труд: без reviewer-а инструмент даёт только detected-находки агентов, то есть деградирует до того же, что ScanCode, но дороже в эксплуатации.
  • Ориентирован на тарболлы исходников; на бинарниках и архивах без исходных текстов агенты дают No license found.
  • Это не оркестратор CI и не политика — нет автоматического «падающего gate» по правилу, как в ORT; решение принимает человек.

Offline / on-premise

Полностью автономен и предназначен для self-hosted развёртывания. Сервер, БД и агенты лицензионного анализа работают локально, без обращения к внешним сервисам, что делает FOSSology пригодным для закрытого контура. Разворачивается официальным образом fossology/fossology (all-in-one со встроенным fo-scheduler) или ставится на хост; эталонная база лицензий поставляется вместе с агентами.
