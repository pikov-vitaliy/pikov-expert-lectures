Шаблон протокола пилота SCA инструмента

Назначение Рабочая форма для фиксации результатов пилота SCA/OSA-инструмента: сценарии приёмки, результат pass/fail по каждому, итоговое решение go / no-go. Делает выбор инструмента доказательным, а не «по демо». Шаблон tool-agnostic; конкретный прогон по CodeScoring — в М12 CodeScoring и подготовка пилота.

Когда применяется

На этапе выбора/закупки инструмента, до признания соответствия ТЗ. Один протокол — один пилот; заполняется по ходу прогона на реальных сборках Организации.

Чек-лист подготовки

  • [ ] Развёрнут тестовый контур (серверы, БД, сеть, доступы зафиксированы).
  • [ ] Подключён хотя бы один CI-пайплайн.
  • [ ] Загружены реальные проблемные сборки (включая C/C++ legacy).
  • [ ] Согласованы приёмочные сценарии и пороги.
  • [ ] Назначены роли наблюдателей от ИБ, разработки, юристов.

Итоговое решение

Go / No-Go Решение принимается по закрытым приёмочным сценариям, а не по общему впечатлению.

  • [ ] Go — все блокирующие сценарии Pass, остаток оформлен как риск со сроком.
  • [ ] Go с условиями — есть Fail, но закрываются договорной гарантией/доработкой (перечислить).
  • [ ] No-Go — блокирующие сценарии Fail без пути закрытия.
