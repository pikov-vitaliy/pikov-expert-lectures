Реестр unresolved libraries

Назначение

Журнал нераспознанных компонентов: всё, что инструмент увидел, но не смог однозначно сопоставить с purl/cpe (vendored-исходники, статическая линковка, кастомные сборки C/C++, alias CPE). Делает «не распозналось» видимым и управляемым, а не молчаливо потерянным.

Когда применяется

Заполняется по результату форматных чек-листов и порядка работы с неопознанной библиотекой, который поставляет в реестр новые записи. Ведётся как живой worklist до закрытия каждой строки.

Реестр vs порядок Этот документ — таблица состояния (что не распознано и в каком статусе). Пошаговый разбор каждой записи — в Порядок работы с неопознанной библиотекой. Они ссылаются друг на друга: порядок → запись в реестре → закрытие.

ID Артефакт / симптом Поставка Тип проблемы Кандидат-purl Статус Владелец Срок

UNR-003 cpe не сопоставился cpe alias — alias worklist роль дата

Типы проблем

  • static link — статически слинкованный артефакт без сборочного контекста (см. П23. Статическая линковка как слепая зона).
  • vendored — исходники без апстрима/менеджера пакетов.
  • cpe alias — компонент есть, но cpe не совпадает (см. П25. CPE alias worklist).
  • binary — готовый бинарник без распознаваемых координат.
  • format gap — компонент выпал из SBOM при генерации.

Статусы записи

Статус Значение

эскалация запрошены данные у соисполнителя
закрыта-идентифицирована получен purl, заведён паспорт
закрыта-риск принят оставлена с принятым риском, есть срок пересмотра

Правила ведения

  • [ ] Каждая запись имеет владельца и срок (бессрочных «висяков» нет).
  • [ ] Закрытие «идентифицирована» сопровождается заведением паспорта компонента.
  • [ ] Закрытие «риск принят» ссылается на П30. Исключения и принятие риска.
  • [ ] Доля unresolved сверяется с порогом соглашения о качестве.
