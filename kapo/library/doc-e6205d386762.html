Чек-лист SBOM for AI

Назначение

Рабочая форма проверки полноты SBOM для системы с компонентами ИИ (модели и датасеты): расширяет обычный SBOM продукта элементами модели, обучающих данных и инфраструктуры. Цель — убедиться, что AI SBOM не сводится к списку Python-пакетов и описывает то, что отличает AI-систему: веса, данные, их происхождение и лицензии.

Когда применяется

  • Приёмка поставки, содержащей обученную модель или внешний датасет.
  • Подготовка релизного evidence для продукта с AI-функциональностью.
  • Аудит поставщика AI-компонента на минимальные элементы.

Metadata

  • [ ] Указаны author, version, format, инструмент генерации (генератор фактов) и timestamp.
  • [ ] Зафиксирован контекст генерации (что и из чего собрано) и dependency relationships.
  • [ ] SBOM подписан или есть иной механизм проверки целостности и авторства.

System-level properties

  • [ ] Указаны имя системы, производитель, версия и состав компонентов.
  • [ ] Описаны data flow и data usage (как данные ходят через систему).
  • [ ] Зафиксированы input/output properties и область применения (application area).

Models

  • [ ] Для каждой модели: имя, идентификатор, версия, производитель.
  • [ ] Есть hash весов модели или явно указано unknown.
  • [ ] Зафиксированы training properties и архитектурные свойства модели.
  • [ ] Указана лицензия модели отдельно от лицензий runtime-компонентов.
  • [ ] Есть external references (карточка модели, источник).

Datasets

  • [ ] Для каждого датасета: имя, описание, состав, идентификатор.
  • [ ] Есть hash датасета или явно unknown.
  • [ ] Зафиксирован provenance (происхождение) и dependency relationship к модели.
  • [ ] Описаны статистические свойства и чувствительность данных (PII/секретность).
  • [ ] Указана лицензия датасета отдельно от лицензии модели.

Infrastructure

  • [ ] Перечислены runtime, фреймворки, пакетные менеджеры и их версии.
  • [ ] Указано специализированное железо / ссылка на HBOM, если применимо.

Security properties

  • [ ] Перечислены применённые контроли и сведения о соответствии (compliance).
  • [ ] Есть vulnerability referencing и связь с triage-процессом (VDR/VEX).
  • [ ] Зафиксирована применимая cybersecurity policy.

KPI

  • [ ] Приведены метрики безопасности и операционной производительности (если требуются заказчиком).

AI SBOM ≠ обычный SBOM Если в отчёте есть только Python-зависимости, но нет модели, датасета, их лицензий и происхождения — это SBOM приложения, а не SBOM AI-системы. Явно укажите, чем AI SBOM расширяет обычный.

Три разные лицензии Лицензия модели, лицензия датасета и лицензии runtime-кода — независимы и часто конфликтуют (например, non-commercial-датасет в коммерческом продукте). Их нельзя сворачивать в одно поле.
