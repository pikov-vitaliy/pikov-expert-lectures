Шаблон юридического заключения по лицензии

Назначение

Структурированная форма юридической оценки лицензии конкретного компонента: какие обязательства она накладывает, совместима ли с моделью поставки продукта Организации и можно ли её использовать (и на каких условиях). Заключение — обязательное evidence для исключения и для допуска неизвестной лицензии.

Когда применяется

  • Компонент попал в класс «сильный copyleft» или «запрещённые» по политике.
  • Лицензия не определена или конфликтная (NOASSERTION, двойное лицензирование).
  • Модель использования нестандартна (статическая линковка copyleft, сетевой сервис с AGPL).

Форма заключения

Раздел Содержание
Объект оценки компонент@версия (PURL), назначение в продукте
Лицензия SPDX-выражение(я); источник определения (файл LICENSE / манифест / реестр)
Тип обязательств permissive / weak copyleft / strong copyleft / proprietary / неопределённая
Триггер обязательств распространение, модификация, сетевое использование, статическая линковка
Совместимость с моделью поставки (проприетарный дистрибутив / SaaS / встраивание)
Обязательные действия сохранить NOTICE, раскрыть изменения, обеспечить замену библиотеки, и т.п.
Ограничения и запреты non-commercial, патентные оговорки, запрет на сублицензирование
Вывод использовать допустимо / допустимо с условиями / недопустимо
Условия допуска конкретные меры (тип линковки, изоляция, тексты лицензий)
Остаточные риски что остаётся даже при соблюдении условий
Срок действия оценки дата пересмотра (лицензия версии может измениться)
Подготовил / согласовал роль (без конкретных ФИО)

Принцип трактовки «AND нескольких лицензий — соблюдаем все одновременно; OR — выбираем одну совместимую. Молчание о лицензии трактуется как отсутствие разрешения на использование, а не как разрешение».

Сетевое использование меняет всё Для AGPL-3.0 предоставление доступа к функциям компонента по сети приравнивается к распространению и запускает обязательство раскрытия исходного кода всего сервиса. Это фиксируется в разделе «Триггер обязательств» явно.

Правила оформления

  • Оценка привязана к конкретной версии: при обновлении компонента заключение пересматривается.
  • Вывод «допустимо с условиями» обязателен к переносу в Реестр исключений с теми же условиями.
  • Без раздела «Остаточные риски» заключение неполно — даже permissive-лицензии несут patent/attribution-обязательства.
