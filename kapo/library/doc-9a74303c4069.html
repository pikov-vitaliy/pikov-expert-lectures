CycloneDX ECMA-424

О документе

Что это ECMA-424 — стандарт Ecma International, закрепляющий спецификацию CycloneDX как формат Bill of Materials. Издан техническим комитетом TC54; развитие самого формата ведёт проект OWASP CycloneDX. Это не методичка по управлению уязвимостями, а схема данных: как машинно описать состав продукта и связанные с ним факты безопасности.

CycloneDX покрывает не только классический SBOM (компоненты), но и связанные типы BOM: VEX (статус эксплуатируемости уязвимости), VDR (раскрытие найденных уязвимостей), CBOM (криптография), а также блоки compositions (полнота описания) и evidence (откуда инструмент узнал о компоненте). Сериализация — JSON, XML или Protocol Buffers; в курсе рабочий вариант — JSON.

Ключевые требования

  • Идентификация документа. Корень содержит bomFormat: "CycloneDX", specVersion, serialNumber (URN-uuid) и version (ревизия самого BOM) — без них документ не самоописателен.
  • Идентификация компонентов через purl. Каждый component несёт type, name, version; для матчинга на уязвимости — purl в формате pkg:type/namespace/name@version, при наличии — cpe.
  • Прослеживаемость до субъекта поставки. Секция metadata фиксирует timestamp, tools (чем сгенерирован BOM) и metadata.component (что именно описывается).
  • Честность охвата. Блок compositions с aggregate (complete / incomplete / unknown) обязателен, когда состав описан не полностью — иначе SBOM молча выдаёт частичную картину за полную.
  • Разделение факта и решения. Уязвимость как факт живёт в vulnerabilities; решение «эксплуатируема ли она в продукте» — это VEX-analysis.state (exploitable, not_affected, in_triage…), а не свойство компонента.
  • Доказуемость происхождения данных. Блок evidence (identity, occurrences, call-stack) показывает, на каком основании инструмент приписал компонент продукту.

Что считать evidence

Артефакты соответствия - Валидный CycloneDX JSON с заполненными metadata.timestamp, metadata.tools, serialNumber, version — основной ППК продукта. - Отчёт проверки против официальной JSON-схемы CycloneDX соответствующей specVersion (gate в CI). - Заполненный compositions.aggregate для C/C++-сборок, где статическая линковка делает охват incomplete. - VEX-документ CycloneDX с analysis.state/justification по каждой значимой уязвимости. - Метрика качества: доля компонентов с валидным purl и непустой version.
